# 0.7.9 manual test plan

Pairs with the automated tests. Automated coverage is listed per item so you only
hand-check what a test cannot reach.

| Change | Repo | Automated |
|---|---|---|
| The click-to-select tool survives a preview reload | LlamaBot | 6 tests, `app/tests/js/element_selector_rearm_on_load.test.mjs` |

Frontend-only — a hard refresh picks it up, no container restart, no image rebuild.

**Run the JS suite through its pytest wrapper, in the container** — that is the path CI
uses, and the only one that works there:

```
docker exec -w /app/app leonardo-llamabot-1 python -m pytest tests/test_frontend_element_selector_rearm_js.py -q
```

A bare `node --test` inside the container fails nearly everything: node 18 reads the
imported `app/frontend/*.js` sources as CommonJS, so every named import throws. The
wrapper's `--experimental-default-type=module` flag is what fixes that, which is also why
**a new `tests/js/*.test.mjs` file is invisible to CI until its
`app/tests/test_frontend_<name>_js.py` wrapper exists**. This change adds
`test_frontend_element_selector_rearm_js.py`.

## The click-to-select tool survives a preview reload

Reported from the CRM box (`crm-4`, 2026-09-10): "the little mouse select tool in llamabot
chat.html isn't working on the iframe". The button lit up, nothing highlighted, and it took
three clicks to recover.

The parent posted `enable-element-selector` into the iframe exactly once and never
re-checked that the iframe agreed. Now it re-sends on every iframe `load`.

**What you need:** any box with a Rails app in the preview pane and at least one page with
clickable text. A slow-loading app makes case A much easier to hit.

### A. Click the tool while the preview is still loading

1. Open the chat. In the preview pane, navigate to any page (or ask Leo to make an edit, so
   the frame reloads).
2. **Immediately**, while the page is still visibly loading, click the element-selector
   button (the mouse-pointer icon by the message box).
3. Wait for the page to finish loading.
4. Hover over the page.

- **Expect:** elements highlight on hover, and the button is lit. One click on an element
  drops it into the message box as a badge.
- **Before the fix:** the button was lit but nothing highlighted; the next click turned the
  button off without ever having been on, so you needed three clicks total.

### B. Turn the tool on, then let the preview reload

1. With the preview fully loaded, click the element-selector button. Confirm hovering
   highlights elements.
2. Ask Leo to make any edit to the app, and wait for the preview to reload on its own.
   (Or navigate with the preview's own URL bar — same thing.)
3. Without touching the button, hover over the reloaded page.

- **Expect:** elements still highlight. The button was lit the whole time and it is telling
  the truth.
- **Before the fix:** highlighting was dead after the reload while the button stayed lit.

### C. The tool does not turn itself on behind your back

1. Make sure the element selector is **off** (button not lit).
2. Reload the preview a few times — navigate, or have Leo edit a file.
3. Hover over the page.

- **Expect:** nothing highlights, ever. A reload must not enable a tool you did not ask for.

### D. Turning it off stays off

1. Turn the tool on, then click the button again to turn it off.
2. Let the preview reload.
3. Hover.

- **Expect:** nothing highlights.

### E. Picking an element still ends selection mode

1. Turn the tool on, click an element. It should appear as a badge above the message box
   and the button should go unlit.
2. Let the preview reload.
3. Hover.

- **Expect:** nothing highlights — one pick is one pick. Click the button again to select a
  second element; the badges accumulate (1st, 2nd, ...).

## Known: this box's model tests are red, and it is not this change

`.leonardo/model_policy.json` on a dev box is pushed by the mothership and narrows the
model allowlist, so `is_model_enabled('deepseek-v4-flash')` is False where the repo's tests
expect True. That reds out 50 tests across `test_model_policy.py`,
`test_default_model_policy.py`, `test_model_registry_consistency.py`,
`test_provider_key_never_leaks_openai.py`, `test_openrouter_registry.py` and
`test_custom_agent_modes.py`.

Verified as pre-existing by an A/B on this branch — the same six files report **50 failed /
300 passed** both with this change applied and with it fully removed. Do not chase it from
inside a frontend PR.
