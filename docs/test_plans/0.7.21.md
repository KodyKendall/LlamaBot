# 0.7.21 test plan

## LP-47: saved versions of the whole app

Automated: `app/tests/test_app_versions.py` (proxy paths, user attached, typed confirm,
messages verbatim, field + link allowlist, role boundary, Leo's backup guidance) and
`app/tests/js/app_versions.test.mjs` (render states, confirm wording, requests,
restore-finished rule, a11y wiring). Contract: `docs/dev/app_versions_contract.md`.

Needs the mothership half of LP-47 live and a **non-customer** box. Sign in as the box owner.

**Save**
- [ ] History panel opens with **Versions** at the top, above the Git save status.
- [ ] Save version → name "v1" → Save: "v1" appears with **Saving**, then **Saved** with a date and a size. The status line says `"v1" saved.`
- [ ] Empty name: "Give this version a name.", nothing is created.
- [ ] On a plan at its limit: Save shows the mothership's own message and a "See plans and pricing" link.

**Restore**
- [ ] Change a file, delete a table's rows, upload a file. Restore "v1": the dialog says the date, "Your current app is saved first", "about 2 minutes".
- [ ] The Restore button stays off until you type `v1`.
- [ ] Confirm: the panel shows "Restoring your app to "v1"…"; the page reloads by itself when the box is back.
- [ ] After reload: code, rows and uploaded file are back as they were. A **safety** version from just before the restore is in the list.
- [ ] Chat reconnects and the preview loads without a manual refresh.

**Start new Leo**
- [ ] "Start new Leo from this" on "v1": dialog says the current app stays as it is → confirm → "Your new Leo … is starting" + "Open your dashboard" link.
- [ ] The new box boots on the dashboard with v1's code, data and files. The original box is unchanged.

**Delete**
- [ ] Delete "v1" → confirm: it leaves the list. The running app is unchanged.

**No way out (LP-45)**
- [ ] DevTools → Network while doing all of the above: no response has an S3 / `amazonaws` / signed URL, and no button or link downloads anything.
- [ ] Ask Leo "make me a backup of my app": Leo points at **Save version in the History panel** and builds nothing.

**Accessibility**
- [ ] Keyboard only: Tab to Save version, type a name, Enter saves; Escape closes the name form.
- [ ] Each dialog: focus starts inside, Tab stays inside, Escape cancels, focus returns to the button that opened it.
- [ ] Screen reader (VoiceOver/NVDA): Saving / Saved / Restoring are read out; buttons read "Restore version v1", "Start new Leo from this: v1", "Delete version v1".

**Roles and off switches**
- [ ] Security-only admin: sees the list, but Save/Restore return "Your role does not include this".
- [ ] Mothership flag off (`enabled: false`, no message): the Versions section is gone, Git history still works.
- [ ] Box with no mothership (`instance.json` missing): the section says versions are for LlamaPress-hosted apps, no buttons.

**Post-release, one internal fleet box**
- [ ] HTTPS loads, sign-in works.
- [ ] One save + restore cycle end to end; the mothership audit log has the row.

## LP-51: pull images from registry.llamapress.ai, Docker Hub fallback

Automated: Leonardo `test/bin_update_image_source.sh` (mock docker; default path unchanged,
registry pull + retag, per-service fallback for no_key / login_failed / tag_not_found /
timeout / digest_mismatch, both-fail, logout + key-leak checks). Runs in Leonardo CI.

Needs a **non-customer** box (qa-candidate or an internal box) and a box key from the
mothership, passed at run time only: `lxc exec <box> --env IMAGE_SOURCE=registry --env BOX_LICENSE_KEY=… -- …`.

- [ ] No `IMAGE_SOURCE`: update log shows one `pulling:` + `pull ok`, then `image_source=dockerhub` per service; no registry login.
- [ ] `IMAGE_SOURCE=registry`, valid key, mirrored tag (0.7.20): log shows `image_source=registry` for both services; `.leonardo/last_update.json` has `image_sources`; row appears on llamapress.ai/admin/image_pulls.
- [ ] `docker images | grep registry.llamapress.ai` is empty; containers run `kody06/<name>:<tag>`; digest matches Docker Hub (`docker manifest inspect kody06/<name>:<tag>`).
- [ ] Revoked key: update succeeds, `fallback_reason=login_failed`.
- [ ] Tag not mirrored: update succeeds, `fallback_reason=tag_not_found`.
- [ ] `registry.llamapress.ai` pointed at a black hole in `/etc/hosts`: falls back within 10 minutes (`timeout` or `login_failed`), update succeeds.
- [ ] After every run: `grep -rF "<key>" .env .leonardo/ ~/.docker/` returns nothing.
