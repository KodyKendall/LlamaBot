Pairs with the automated tests. Automated coverage is listed per item so you only
hand-check what a test cannot reach.

| Change | Repo | Automated |
|---|---|---|

| LP-24: `GET /llama_bot/uploads[/:name]` — 401 without/forged token, box + agent token accepted, paging, `q`, 404 on traversal and symlinks, re-read on change, `uploads_authorizer` 403 + index filter | llama_bot_rails | `spec/controllers/llama_bot_rails/uploads_controller_spec.rb`, `spec/requests/llama_bot_rails/uploads_spec.rb` (traversal through the real router) |

Not covered by automation: XLSX/XLS/XLSM go through roo, which is in the app image
but not the gem's dev bundle. XLSX/XLSM were checked by hand on llamapress-dev
(2026-10-29) against the real image; `.xls` (legacy) was not. `.doc` (legacy Word)
reads only if `antiword` is installed, and the stock image doesn't have it, so it
comes back `unsupported`.

Setup: a box on the 0.7.19 llamapress-simple image (the gem ships inside it) and the
0.7.19 LlamaBot image. On an older Rails image the tool says the gem is too old.

## Custom mode reads uploads

Needs a custom mode built with `standard_tools()` (see
`docs/cookbooks/register-custom-leo-mode.md`), and a signed-in Rails user.

- [ ] Drop a CSV into chat and ask "what's in this file?" Leo calls
      `read_uploaded_file` and answers from the rows.
- [ ] Same with an XLSX that has two sheets. The answer covers both sheets.
- [ ] Same with a DOCX and a text PDF.
- [ ] Ask for one row in a big spreadsheet ("what's Ada's email?"). Leo uses `q`
      and doesn't page through the whole file.
- [ ] Drop a scanned (image-only) PDF. Leo says it has no readable text. It does
      not make text up.
- [ ] Sign out of the app panel and ask again. Leo tells you to sign in, and
      makes no tool call first.

## rails_agent (Engineer mode)

- [ ] Drop an XLSX into chat and ask Leo to summarise it. Leo calls
      `read_uploaded_file`, not a bash/Roo script.
- [ ] Works while signed out of the Rails app panel (this uses the box token).
- [ ] Ask Leo to import the spreadsheet's rows into a model. Writing a script for
      that is fine. It's processing, not reading.

## Security

- [ ] `curl -i https://rails-<box>.llamapress.ai/llama_bot/uploads` with no header
      returns **401** and no file names.
- [ ] `curl -i https://rails-<box>.llamapress.ai/llama_bot/uploads/..%2Fconfig%2Fmaster.key`
      returns **401** (no token) — and **404** with a valid token.
- [ ] Signed into the app in a browser, open `/llama_bot/uploads`. Still **401**. A
      browser session is not enough.

## LP-26: feedback bubble pinned on iPhone/iPad Safari

Needs a real iPhone or iPad (Safari), signed into an app with a wide table (e.g. RSB `/projects`).

- [ ] Open the page. The purple bubble sits in the bottom-right corner of the screen.
- [ ] Scroll the table right, then down. The bubble stays in the corner the whole time.
      It never sits over a row's edit/delete icons.
- [ ] Pinch-zoom in, then pan around. The bubble stays in the corner and stays the same size.
- [ ] Rotate to landscape. Bubble moves to the new bottom-right corner, clear of the notch.
- [ ] Tap the bubble. The panel opens above it, fully on screen. Send a feedback message.
- [ ] Desktop Chrome and Safari: bubble sits bottom-right as before, panel opens as before.

## Ask-before-edits covers sub-agents

Needs a chat in ask-before-edits mode (a WebSocket message with `ask_before_edits: true`;
the mode menu doesn't offer it).

- [ ] Ask Leo to "use delegate_task to add a footer". An approval card shows before any
      sub-agent starts. Reject it. No files change.
- [ ] Ask Leo to "use delegate_research to find the User model". Approval card shows.
      Approve it. Findings come back.
- [ ] Ask Leo to restart Rails. Approval card shows before the restart.
- [ ] Normal mode (no ask flag): delegate_task and delegate_research run with no prompt, as before.
- [ ] In normal mode, ask delegate_research for a row count. It hands back the
      `rails runner` command instead of running it.

## LP-12: project notes capped + Plan mode builds after approval

Needs a box with a big `.leonardo/LEONARDO.md` (paste ~200 KB of `## Section` notes
into it if you have no real one). Watch the token indicator.

- [ ] Start a new chat. First-turn input tokens are ~12k for notes + the base prompt
      (well under 84k). `LEONARDO.md` on disk is unchanged.
- [ ] Ask "what's at the top of your project notes?" — Leo knows it.
- [ ] Ask about something near the bottom of the file. Leo calls `read_leonardo_md`.
- [ ] Ask Leo to "remember session status for today". It refuses the status log and
      offers to save a lasting fact instead.
- [ ] Ask Leo to remember the same topic twice with a date in the name. Only one
      file in `.leonardo/memory/`, owned by `ubuntu` (uid 1000). `MEMORY.md` lists
      names + one-liners only, no bodies.
- [ ] Plan mode: ask for a small feature, answer the questions, then reply "go" on the
      approval card. Leo starts editing files in that same turn — no new question card.
- [ ] Ask Leo for the git status of the app. It uses the `git_status` tool, never `git init` in `/rails`.

## LP-10: Inbox/Activity after chat SSO

Needs a mothership-managed box (new llamapress-simple image + this LlamaBot), a
LlamaPress.ai admin, and a private window (signed out of the Rails app).

- [ ] Open the box chat. Click "Sign in with your LlamaPress.ai account". Chat signs in.
- [ ] Open the Inbox tab. It shows your messages, not a sign-in form.
- [ ] Open the Activity tab. It shows the activity feed, not a sign-in form.
- [ ] Old-image check: if a framed sign-in page does show, it has no SSO button and
      moves on by itself within a few seconds of signing in.
- [ ] Visit `https://rails-<box>.../users/sign_in` directly (not framed). The SSO button
      is there and signs you in back to the Rails app.
