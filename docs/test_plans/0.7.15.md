# 0.7.15 manual test plan

Pairs with the automated tests. Automated coverage is listed per item so you only
hand-check what a test cannot reach.

| Change | Repo | Automated |
|---|---|---|
| Chats are private to whoever started them (LP-6) | LlamaBot | 18 in `test_thread_ownership.py` (owner recorded, `/threads` + cursor, `/chat-history`, token count, compact, WS message/attach/cancel/resume, backfill) |
| New chats show in history; reload re-opens your last chat (LP-5) | LlamaBot | 12 in `app/tests/js/thread_list_refresh.test.mjs` (CI via `test_frontend_thread_list_refresh_js.py`); one real-browser pass on the dev box |
| Discarding a whole app warns first; Undo stays in chat (LP-7) | LlamaBot | 10 in `test_discard_warning_and_undo_card.py` (counts, pending marker, dismiss) + 15 in `app/tests/js/discard_warning.test.mjs` (CI via `test_frontend_discard_warning_js.py`); browser pass with stubbed checkpoint API |

LP-6 is Python and needs `docker compose -f docker-compose-dev.yml up -d --force-recreate llamabot`. LP-5 is frontend-only: a hard refresh is enough. LP-7 is both (new `/discard/dismiss` endpoint).

## Private chat history (LP-6)

Rule shipped: Option A. Chats from before 0.7.15 go to the box's only user at boot. On a
box with several users they stay unowned and only admins see them.

- [ ] Create two non-admin users (A and B) on a dev box.
- [ ] As A, start a chat and send "Private note from A".
- [ ] As B, in another browser, open the history menu. A's chat is not listed.
- [ ] As B, open `/chat-history/<A's thread id>`. It returns the same body as a made-up
      id (`values` is `{}`), with no messages and no `history_missing`.
- [ ] As B, with more than five chats each, click "Load more...". Every row is B's.
- [ ] As A, the chat is still at the top of the list and opens normally.
- [ ] As an admin, the menu shows the admin's own chats plus any unowned old ones.
- [ ] On a single-user box with old chats, upgrade (force-recreate). The llamabot log shows
      "Assigned N unowned chats to the box's only user" and the menu lists the same chats as before.
- [ ] The chat embedded in the box's Rails app (llama_bot_rails gem) still sends and replies.

## New chat in history, last chat re-opens (LP-5)

- [ ] Open Leo. Click New, send a message, wait for the reply.
- [ ] Open the history menu without reloading. The new chat is at the top, "Just now".
      The old list stays on screen while it refreshes (no "Loading" flash).
- [ ] Click "Load more...". No chat is listed twice.
- [ ] Reload. The same chat opens with its messages.
- [ ] Click a link that takes the Leo window to another page, then press Back. The chat is still there.
- [ ] Click New, then reload. A blank chat opens, not the older one.
- [ ] Open Leo with `?prompt=hello`. It starts a fresh chat, not the remembered one.
- [ ] Repeat the menu and reload steps in Chrome, Edge and Safari.

## Discard warning and Undo card (LP-7)

Do this on a throwaway box or a scratch copy: Discard really stashes and cleans the
Leonardo tree. Strings are English only (the chat UI has no i18n).

- [ ] Add 60 untracked files, including a few under `rails/app/controllers` and
      `rails/app/models`. Click Discard in the History panel. A modal says "This will
      remove N files, including X controllers and Y models. Your app will stop working
      until you undo." No browser confirm box.
- [ ] Click "Save a checkpoint instead". Nothing is discarded; the save form opens.
- [ ] Click Discard again, then "Discard N files". An amber "Undo discard" card appears above
      the chat input.
- [ ] Close the panel and reload. The card is still there.
- [ ] Click New chat. The card is still there.
- [ ] Click "Undo discard". Every file comes back and the card goes away. Reload: no card.
- [ ] Discard again, then click × on the card. It goes away and stays gone after reload; the
      panel's own "Undo discard" still restores the files.
- [ ] With one edited, already-committed file, Discard shows the old light confirm.

## Signed-out feedback keeps the element and images (LP-9)

Needs the 0.7.15 llamapress-simple image (gem) and the Leonardo `feedback_bubble.js`.
Set `config.llama_bot_rails.anonymous_feedback_enabled = true`, then use a private
window where you are NOT signed in.

- [ ] Open the purple bubble. Element picker, screenshot and paperclip show; video does not.
- [ ] Pick an element, paste an image, type a note, Send. "Thanks for your feedback!" shows.
- [ ] Open the saved item (signed in). It has the note, the element, the page link and the image.
- [ ] The element preview renders; "View HTML" shows the markup as text.
- [ ] Paperclip a PDF. It is refused before upload: "Not attached: x.pdf: not an image".
- [ ] Attach 4 images. The 4th is refused with "only 3 images allowed".
- [ ] Attach an image over 5 MB. Refused with "over 5 MB".
- [ ] Signed in: video and PDF attachments still work as before.
- [ ] Turn `anonymous_feedback_enabled` off. Signed out, the bubble does not appear.
