# 0.7.14 manual test plan

Pairs with the automated tests. Automated coverage is listed per item so you only
hand-check what a test cannot reach.

| Change | Repo | Automated |
|---|---|---|
| Base plan paywall card leads with connecting ChatGPT | LlamaBot | 4 tests, `app/tests/js/paywall_card_copy.test.mjs` |
| A chat with lost history says so instead of greeting | LlamaBot | 5 tests, `test_chat_history_missing.py` + 2 in `app/tests/js/thread_history_missing.test.mjs` |
| Rails container no longer sees shared AWS / DeepSeek keys | Leonardo | 9 checks, `test/rails_env_optin.sh` (`docker compose config`, no containers) |
| Chat recovers or shows an error when sign-in fails | LlamaBot | 3 in `test_websocket_auth_failure_closes.py` + 18 in `app/tests/js/ws_auth_failure_recovery.test.mjs`; browser probe `~/dev/probes/zz-ws-auth-probe.spec.ts` |
| Question cards take your latest answer, not a stale one | LlamaBot | 3 in `test_question_stale_answer_replay.py` (real plan-mode tool, cancelled run) |
| Finished turns keep one thinking row, not one per step | LlamaBot | 2 in `app/tests/js/thinking_rows_collapse_on_end.test.mjs` (CI via `test_frontend_thinking_rows_collapse_js.py`) |

The `/chat-history`, WebSocket sign-in and question-answer changes are Python and need `--force-recreate llamabot`. The other
two LlamaBot changes are frontend-only, so a hard refresh is enough.

## Chat sign-in failure

- [ ] Open the chat, then in devtools set `localStorage.llamabot_ws_token` to any wrong JWT
      (keep `llamabot_ws_token_expiry` in the future) and reload. Send a message: Leo answers,
      no reload needed. Network tab shows a second `/ws` and one `/api/ws-token`.
- [ ] Same, but sign out of LlamaBot in another tab first. Within a few seconds the chat
      shows "Leo could not sign you in. Refresh the page to continue." with a Refresh button,
      and the message shows "Your message was not delivered." with Retry. No spinner.
- [ ] Refresh works. Retry after signing back in delivers the message once (no duplicate turn).
- [ ] A normal message on a healthy chat never shows "not delivered".

## Question card answers

The stale case needs a run cancelled in a split second, so it is covered by the test, not by hand.
These check nothing else broke.

- [ ] Plan mode: when the question card shows, click an option. Leo continues with that answer.
- [ ] Next card: type a reply in the main chat box instead of clicking. Leo treats it as the
      answer (the card closes, no "Error resuming").
- [ ] After that, send another normal message. Leo replies to it, not to the earlier answer.
- [ ] In the llamabot logs, "still holds an answer from a cancelled run" only ever appears after
      a turn was cancelled (Stop pressed, or a new message sent mid-turn).

## One thinking row per finished turn

- [ ] Hard refresh. Ask Leo something that takes several tool calls (e.g. "how much did we spend last month, by category?").
      While it works, stacked "thinking..." rows are fine.
- [ ] When the answer lands, only one "thinking..." row is left, directly above the answer.
      No dead space between your question and the reply.
- [ ] Click that row: it expands and shows the reasoning from every step, not just the last.

## Error row on a narrow chat panel

- [ ] Drag the chat panel down to its narrowest. Hover the row: "Read more" and "Show Leo" sit
      apart (on a second line if needed), nothing runs off the edge, no text overlaps.
- [ ] At the narrowest width the summary ends in "…"; hovering it shows the full text.
- [ ] Click "Read more" (popup opens), tick/untick "Show Leo", click × — each does its own thing.

## Voice dictation (mic button)

Needs `ASSEMBLY_AI_API_KEY` in the instance `.env` and a
`--force-recreate` of llamabot. Typing the words is not the test — speak them.

- [ ] Remove the key and recreate: Settings → Voice Dictation is greyed out, off, and says the key is missing. No mic button in chat.
- [ ] Put the key back and recreate: the toggle is clickable but still **off**. Still no mic button in chat.
- [ ] Turn it on, hard-refresh chat: a mic button sits right next to Send.
- [ ] Type `Context: `, click the mic. Allow the mic if asked. The button goes red with a pulsing dot.
- [ ] Say "Add a Rails model called Invoice in PostgreSQL". Words appear after `Context: ` as you speak.
- [ ] Click the mic again. The final, capitalised sentence settles within about a second. **Nothing is sent.**
- [ ] Edit the text, press Send. It sends once, normally.
- [ ] Click into the middle of some typed text, dictate: the words go in at the cursor, nothing after it is lost.
- [ ] Block the microphone for the site, click the mic: a short "Microphone access is blocked" message, button back to normal, chat still works.
- [ ] Send while still dictating: the box clears and stays clear.
- [ ] Repeat the main flow in Chrome, Edge, Safari (Mac) and Safari on iPhone.
