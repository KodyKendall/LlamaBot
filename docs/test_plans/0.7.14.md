hand-check what a test cannot reach.

two LlamaBot changes are frontend-only, so a hard refresh is enough.

## Chat sign-in failure

- [ ] Open the chat, then in devtools set `localStorage.llamabot_ws_token` to any wrong JWT
      (keep `llamabot_ws_token_expiry` in the future) and reload. Send a message: Leo answers,
      no reload needed. Network tab shows a second `/ws` and one `/api/ws-token`.
- [ ] Same, but sign out of LlamaBot in another tab first. Within a few seconds the chat
      shows "Leo could not sign you in. Refresh the page to continue." with a Refresh button,
      and the message shows "Your message was not delivered." with Retry. No spinner.
- [ ] Refresh works. Retry after signing back in delivers the message once (no duplicate turn).
- [ ] A normal message on a healthy chat never shows "not delivered".

## Question card answers

The stale case needs a run cancelled in a split second, so it is covered by the test, not by hand.
These check nothing else broke.

- [ ] Plan mode: when the question card shows, click an option. Leo continues with that answer.
- [ ] Next card: type a reply in the main chat box instead of clicking. Leo treats it as the
      answer (the card closes, no "Error resuming").
- [ ] After that, send another normal message. Leo replies to it, not to the earlier answer.
- [ ] In the llamabot logs, "still holds an answer from a cancelled run" only ever appears after
      a turn was cancelled (Stop pressed, or a new message sent mid-turn).
