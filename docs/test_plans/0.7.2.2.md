## Non-English apps stop showing "Translation missing"

Rails ships English only for its own strings. Any Leo app that added a second language
rendered literal `Translation missing: es.datetime.distance_in_words.x_days` wherever it
used `time_ago_in_words`, `number_to_currency`, dates, or a validation message — 20 times
on one customer's dashboard. `rails-i18n` supplies those strings in ~80 languages, and
`config.i18n.fallbacks` moved from `production.rb` to `application.rb` so a still-missing
key falls back to English **in development**, which is what every Leo box actually runs.

**Setup**

- Change is in the **LlamaPress-Simple base image** — it needs a released image and a
  `bin/update` on the box; a code sync alone will not do it (Gemfile + Gemfile.lock).
- Code: `Gemfile` (`rails-i18n`, `i18n-tasks`), `config/application.rb`.
  Automated coverage: `spec/config/i18n_spec.rb`.
- Any Rails console below: `docker compose exec llamapress bundle exec rails console`.

**The Rails strings**

- [ ] `I18n.t("datetime.distance_in_words.x_days", count: 3, locale: :es)` returns Spanish
      ("3 días"), not a missing-translation string. Confirm `Rails.env` is `development`.
- [ ] `I18n.t("errors.messages.blank", locale: :es)` returns Spanish.
- [ ] `I18n.l(Date.today, format: :long, locale: :fr)` gives a French month name.
- [ ] On a box with a language switcher (e.g. `leo-sepe`), switch to Spanish and load a
      page with relative timestamps. No `Translation missing:` text anywhere on it.

**The fallback**

- [ ] Pick a key the app defines in `en` only. `I18n.t(key, locale: :es)` returns the
      **English** string — not `Translation missing`. (This is the half that only works
      because the setting moved out of `production.rb`.)

**Nothing else moved**

- [ ] `I18n.available_locales.size` is still ~140 (faker registers ~58 of them). If this
      collapsed to a handful, locale config got tightened somewhere and seeds will break.
- [ ] An English user sees exactly what they saw before — dates, currency, validation
      errors all unchanged.
- [ ] The app boots and the existing suite passes: `bundle exec rspec`.

**i18n-tasks (development/test only)**

- [ ] `bundle exec i18n-tasks health` runs and reports missing/unused keys.
- [ ] It is **not** in the production bundle — `bundle list --without development test`
      does not include it.

**After the rollout on `leo-sepe`**

- [ ] Its two workarounds can go: `config/locales/es/date_time.yml` (31 hand-written Rails
      keys) and the manual `I18n::Backend::Fallbacks` include in
      `config/initializers/custom/i18n.rb`. The `AppLocales` list in that file stays.
- [ ] With both removed, the Spanish dashboard still renders fully translated.
