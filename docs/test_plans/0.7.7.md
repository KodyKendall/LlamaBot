## 1. A mid-stream stall moves models instead of retrying

The bug: a provider that streamed 478 chunks and then went quiet was classified
transient, so rung 1 retried the same pinned replica for its whole 60s budget before
anything else got a turn. 38 dead turns across 6 customer boxes in the week of
2026-08-31.

**This is hard to reproduce on purpose** — it needs a provider that accepts a request,
streams, and then stalls. Do not try to fake it by pulling the network cable; that is a
different exception (`httpx.ReadError`) on a different path.

1.1 The cheap check. In the llamabot container:
```
docker exec -w /app/app leonardo-llamabot-1 python -c "
from app.agents.leonardo.resilience import is_midstream_stall, is_transient_error
from langchain_openai.chat_models._client_utils import StreamChunkTimeoutError as E
mid  = E(25.0, model_name='z-ai/glm-5.3-flash', chunks_received=478)
zero = E(25.0, model_name='z-ai/glm-5.3-flash', chunks_received=0)
print('mid  ->', is_midstream_stall(mid),  is_transient_error(mid))
print('zero ->', is_midstream_stall(zero), is_transient_error(zero))"
```
Expect `mid -> True True` and `zero -> False True`. The zero-chunk row is the one that
matters: it must stay retryable, or the 2026-08-26 Muse fix is gone.

1.2 The real check is in telemetry, not in a chat window. After the rollout, watch the
mothership `instance_errors` table for `StreamChunkTimeoutError`. The count should fall
toward zero — not because stalls stopped happening, but because a stall now finishes on
another model and never becomes a customer-facing error.

1.3 If you do catch one live, the box's llamabot log should show
`... stalled after N chunks; finishing this step on <other model>` and the chat should
show the "model substituted" banner above the composer. It should NOT show
`Transient model error ... retrying` for that same stall.

1.4 On a box with only one usable model, confirm the error still reaches chat — and that
it arrives on the FIRST failure rather than ~60 seconds later. Faster failure is the
visible improvement there; there is nowhere else for the turn to go.

## 6. Remote model registry

Needs Mother Leo's half (a `models` key in the pushed `model_policy`) for the remote
path. Everything here is testable now by hand-writing the document the lease tick writes.

6.1 Write a policy document with a `models` entry and point the box at it:
```
MODEL_POLICY_PATH=/tmp/policy.json  with
{"models": {"kimi-k2-thinking-moonshot": {"label": "Kimi K2", "model": "moonshotai/kimi-k2-thinking"}}}
```
The dropdown gains "Kimi K2" with no restart, and `jq .policy.registered_models` lists it.

6.2 An entry naming its own endpoint builds against it — `api_base:
"https://api.meta.ai/v1"` + `api_key_env: ["META_API_KEY","MODEL_API_KEY"]` produces a
client pointed at Meta, not at OpenRouter. (This is the hand-written Muse branch,
expressed as config.)

6.3 **Security gate.** Each of these must NOT appear in the dropdown, and each must log
exactly one "refusing to register it" line — not one per request:

  a. `api_base: "https://evil.example/v1"` with `api_key_env: "ANTHROPIC_API_KEY"`
  b. **`api_base: "https://evil.example/v1"` and NO `api_key_env` at all** — the default
     is `OPENROUTER_API_KEY`, the fleet's shared key. This is the row the first version
     of this plan missed, and the hole it missed was real.
  c. the same with `api_key_env: "SHARED_OPENROUTER_API_KEY"` (the provisioner's twin)
  d. `api_key_env: "TAVILY_API_KEY"` or `"OPENROUTER_MANAGEMENT_API_KEY"` at any host
  e. any key the box holds that no map entry names (`BEDROCK_API_KEY` on this box), with
     no operator `key_hosts` declaration
  f. a lookalike host: `https://api.meta.ai.evil.example/v1` with `META_API_KEY`

6.3b The operator escape hatch works and is narrow: with
`{"key_hosts": {"NOVEL_API_KEY": ["novel.example"]}}` in the host overlay AND
`NOVEL_API_KEY` set, an entry at `novel.example` registers while the same key at any
other host does not. The same declaration inside the PUSHED document does nothing.

6.3c A key the box does NOT hold is still allowed at any host (staging a provider), and
the entry shows "API key not configured".

6.3d `OPENROUTER_BASE_URL` still works — a box behind an OpenRouter proxy must not have
its own compiled entries refused.

6.4 A registered model whose key the box does not hold is greyed out with "API key not
configured", and is never chosen as the box's default or as a mid-turn fallback.

6.5 Precedence: the same entry name in the host overlay and in the pushed document
resolves to the pushed one.

6.6 Blast-radius check — a malformed `models` value (a list, a string, a missing `model`
field) drops only what is broken. The dropdown still renders and chat still works.

6.7 Reversibility: pushing `{"models": {}}` removes the added models and returns the box
to its compiled entries. A push that adds a model must be undoable by a push.

## 10. Tailwind builds again through Leo's shell

The bug: the 0.7.6 base image bakes `TMPDIR=/rails/tmp`, and the `bash_command`
env scrub blanked it to `""`. Tailwind v4 is a Bun single-file binary that
extracts its native watcher addon into `$TMPDIR` and dlopens it, so it died with
`ERR_DLOPEN_FAILED` on every 0.7.6 box the moment Leo touched assets.

Everything here must be done **through Leo's own tool** (ask Leo in chat), not
`docker compose exec` — a founder shell is not scrubbed and will pass either way.
That mistake is why this was written off twice as an invented error.

10.1 Ask Leo: *"run `bin/rails tailwindcss:build` and paste the output"*. It must
print `Done in Ns`. No `ERR_DLOPEN_FAILED`, no `/$bunfs/root/watcher-*.node`.

10.2 Ask Leo to run `echo "TMPDIR=[$TMPDIR]"`. It must print a real path
(`/rails/tmp` on a 0.7.6+ image), **not** `TMPDIR=[]`.

10.3 The scrub must still hold. Ask Leo to run
`printenv OPENAI_API_KEY; printenv DEEPSEEK_API_KEY; printenv VSCODE_PASSWORD`.
All three must print nothing at all.

10.4 A previously-blanked variable is now *unset*, not empty. Ask Leo to run
`echo "[${OPENAI_API_KEY:-DEFAULT-WINS}]"` — it must print `[DEFAULT-WINS]`,
proving the shell sees no variable rather than an empty one.

10.5 Nothing else in the shell broke: `bin/rails db:migrate:status`,
`bundle exec rspec --version` and a `git status` through Leo all still work.

10.6 On a box that had the friction row, confirm it stops recurring at
https://llamapress.ai/admin/agent_friction (category `environment`).
