# 0.7.17 manual test plan

Pairs with the automated tests. Automated coverage is listed per item so you only
hand-check what a test cannot reach.

| Change | Repo | Automated |
|---|---|---|
| Solid Queue runs app jobs inside Puma (adapter, plugin in async mode, queue config) | LlamaPress-Simple | `spec/config/solid_queue_spec.rb` (development boot uses `solid_queue`, test keeps `:test`, Puma plugin + async mode, queue.yml valid) |
| Solid Queue tables reach every box through `db:prepare` | llama_bot_rails | `spec/requests/llama_bot_recurring_tasks_spec.rb` (tables exist, gem migration path is appended) |
| A bad `db/recurring.yml` drops the bad entry instead of stopping Puma | llama_bot_rails | `spec/lib/llama_bot_rails/recurring_schedule_spec.rb` (typo'd class, bad schedule, broken YAML, missing/empty file, env-nested file, built-in cleanup task, restart-needed) |
| Polling SQL stays out of the Rails log | llama_bot_rails | `spec/lib/llama_bot_rails/quiet_polling_spec.rb` |
| Read-only feed `GET /llama_bot/recurring_tasks` | llama_bot_rails | `spec/requests/llama_bot_recurring_tasks_spec.rb` (refuses no/wrong token, lists tasks + last runs, hides built-ins) |
| Scheduled Jobs page shows "App Jobs (Rails, no AI)" | LlamaBot | `test_scheduled_jobs_rails_tasks.py` (client sends box token, 404/down/garbled/no-secret read as unavailable, route auth, page section present) |
| Leo knows how to schedule Rails jobs | LlamaBot | `test_scheduled_rails_jobs_directive.py` (suffix present, survives a mothership prompt override) |

The gem specs run in the **skeleton** suite: only the base image bundles `solid_queue`.

Setup: a box on the 0.7.17 llamapress-simple image (gem bump included) **and** the 0.7.17
LlamaBot image. On llamapress-dev the Rails container runs the fleet compose
(`docker-compose.yml` + override), so test against a locally built skeleton image.

All of the below were checked once on llamapress-dev on 2026-10-27 with a probe job.

## Jobs run on a schedule with nobody signed in

- [ ] Ask Leo: "Every minute, append the current time to tmp/heartbeat.log." Leo writes a
      job in `app/jobs/`, an entry in `db/recurring.yml`, and runs `bin/rails restart`.
      It does not use cron, `rails runner`, or an AI Scheduled Job.
- [ ] Close every browser tab. Wait 3 minutes. `tmp/heartbeat.log` has 3 new lines and
      the LlamaBot logs show no model calls for them.
- [ ] Settings → Scheduled Jobs: the **App Jobs (Rails, no AI)** card lists the task, its
      schedule, its last few runs as FINISHED, and a Next Run like "in 1m".
- [ ] The card says jobs only run while the app is awake.

## Restarts and deploys

- [ ] Restart the Rails container. The heartbeat keeps firing afterwards with no edits.
- [ ] Queue a job for 2 minutes from now (`HeartbeatJob.set(wait: 2.minutes).perform_later`
      in a console), restart the Rails container, and wait: it still runs. (On the old
      `:async` adapter it was lost.)
- [ ] Edit `db/recurring.yml` without restarting: the card says the file changed and needs
      a restart. After `bin/rails restart` the notice is gone and the new schedule runs.

## Mistakes in the schedule do not take the app down

- [ ] Add an entry whose `class:` is misspelled and restart. The app still loads, the other
      tasks keep running, and the card shows a red "`<key>` is not running" line.
- [ ] Break the YAML (an unclosed `[`) and restart. The app still loads and the card shows
      the parse error.
- [ ] Delete `db/recurring.yml` and restart. The app loads, nothing of the app's runs, and
      the card says no app jobs are scheduled.

## Overlap and log noise

- [ ] An every-minute job with `limits_concurrency ... on_conflict: :discard` that sleeps
      90s: runs start every other minute; the overlapping ones are skipped, not queued.
- [ ] Tail the Rails log for a minute with no traffic: no once-a-second
      `solid_queue_ready_executions` SQL lines.

## Degrades cleanly

- [ ] LlamaBot 0.7.17 against a Rails box still on an older image: the card says the app's
      Rails image predates scheduled Rails jobs. Agent jobs above it work as before.
- [ ] A `user`-role account cannot load `/api/scheduled-jobs/rails-tasks` (401/403).

## Memory (record in the PR)

- [ ] Rails container memory before/after on a 2 GiB box. Measured on llamapress-dev:
      331 MiB before, 338 MiB after (async mode). Fork mode measured 662 MiB and was
      rejected.
