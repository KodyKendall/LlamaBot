## Backup picker

- [ ] Open the model picker (toolbar → Model). A **Backup** dropdown sits next to the
      model dropdown and says **Automatic**.
- [ ] It lists only models this box can run — nothing greyed out, no "(No API Key)".
- [ ] Pick DeepSeek V4.1 Flash, reload the page: the pick is remembered.
- [ ] With a mothership policy that sets `fallback_model`, Automatic reads
      "Automatic (<that model>)".

## A real failure

Force one by pointing the primary at a model whose key is wrong (e.g. set
`META_API_KEY` to junk and force-recreate llamabot), backup = DeepSeek V4.1 Flash.

- [ ] Send a message. Leo answers. The banner above the composer says the primary
      rejected the box's API key and that the step finished on DeepSeek V4.1.
- [ ] The toolbar Model button reads "DeepSeek V4.1 (backup)" in amber.
- [ ] Wait 30 seconds: the banner is still there.
- [ ] Click ×: banner gone, toolbar back to "Model".
- [ ] Fix the key, send another message: if the banner was still up it disappears when
      the turn ends cleanly.
- [ ] Set Backup back to Automatic and repeat the failure: Leo falls back to the box's
      policy/fleet choice, not to V4.1.

## LP-20: Save and Push set git up themselves

| Change | Repo | Automated |
|---|---|---|
| Save with no git identity sets `leonardo` / `leonardo@llamapress.ai` and retries once | LlamaBot | `test_git_auto_setup.py` (real git repo, empty HOME: saves, author is leonardo, code container gets the same, an existing name is kept, a configured box never runs setup) |
| Push auth failure runs the /gh-copy sequence and retries once | LlamaBot | `test_git_auto_setup.py` (4 stderr shapes recognised, exactly 2 pushes + 1 sync) |
| Still failing + `ENABLE_GITHUB_BUTTON=true` → sign-in modal, then one more push | LlamaBot | `test_git_auto_setup.py` (`needs_github_auth`), `tests/js/git_auto_setup.test.mjs` (callback fires once, not on denied/expired; retry can't loop) |
| No raw git stderr on screen | LlamaBot | `test_git_auto_setup.py` (save + push failures are one plain sentence) |

Not run live on llamapress-dev: a real Save commits to the Leonardo repo and writes
git config into the code container, so do it on a throwaway box.

Setup: a box with no git identity in either container (`docker compose exec llamabot
git config --global --get user.email` prints nothing) and no `~/.config/gh` on the host.

- [ ] History panel → Save with a description. It saves; no error, no slash command.
      `git log -1 --format='%an <%ae>'` shows `leonardo <leonardo@llamapress.ai>`.
- [ ] `docker compose exec code git config --global user.email` → `leonardo@llamapress.ai`.
- [ ] Set `git config --global user.name Kody` in llamabot, unset the email, Save again:
      the name stays Kody, only the email is filled in.
- [ ] With `ENABLE_GITHUB_BUTTON=true`: Push. The GitHub sign-in modal opens by itself.
      Finish sign-in on github.com: the push runs on its own and says it succeeded.
- [ ] Cancel the sign-in instead: no second push, no raw git text.
- [ ] Sign in on the host only (`gh auth login` as ubuntu), leave the containers empty,
      Push: it succeeds with no modal (credentials copied in the background).
- [ ] With `ENABLE_GITHUB_BUTTON` unset: Push with no credentials anywhere shows
      "Couldn't push because this app isn't connected to GitHub. Ask your administrator
      to connect it." — no modal.
- [ ] Checkpoint dashboard page → Push: the toast shows the same plain sentence.
