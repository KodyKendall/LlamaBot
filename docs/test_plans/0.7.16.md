## Mid-turn messages are queued, not cancelled

- [ ] Ask Leo for something with several steps ("read Gemfile, routes.rb and user.rb one at a
      time, then summarize"). While it works, type a second question and press **Enter**.
      Leo keeps going, and his answer covers both. No "Previous task has been cancelled".
- [ ] Same, but click the **send button** instead of Enter. While Leo works and the box has
      text, the button shows the up arrow (not the stop square) and sends.
- [ ] While Leo works, clear the box. The button turns into the red Stop square. Click it:
      the run stops ("Previous task has been cancelled").
- [ ] Send a message right as Leo finishes his reply. A new turn starts by itself and answers it
      (the spinner comes back without you pressing anything).
- [ ] Send two quick messages while Leo works. Both show as your bubbles, and neither is lost.

## Background research

- [ ] In Engineer mode, ask "Use delegate_research to list the models in app/models and their
      associations." Leo says the research started and his turn ends. A pill reads
      **Research running · 0:0x** above the input and counts up.
- [ ] While the pill is up, send "are you there?". Leo answers right away, saying the
      research is still running. The pill stays up.
- [ ] When the research ends, the pill disappears and Leo posts the findings in a new
      message, without you sending anything.
- [ ] Reload the page. History shows a small grey "Research finished" line before Leo's
      findings, and does not show the raw findings as a message from you.
- [ ] Start research, then switch to another chat. That chat shows no pill. Switch back:
      the pill is there with the right time.
- [ ] Start research, then press Stop. The pill disappears and no findings arrive later.
- [ ] Plan mode (or Ticket mode): research inside a planning flow still ends with a plan
      once the findings arrive.

## Known limits (v1)

- Research lives in memory: restarting the llamabot container loses research that is still
  running (no findings, the pill is gone after a reload).
- After a full page reload while research is running, the pill only comes back if this tab
  reattaches to a running turn. The findings still arrive.
- Coding tasks live in memory too: a container restart mid-task loses the report (any edits
  already written stay on disk).
- Only `write_file` / `edit_file` / git tools wait for a coding task. `bash_command` does not
  (so Leo can still answer "how many users?"), which means a `rails generate` run from the main
  chat could still collide with a coding task.
- Ticket mode has its own `delegate_task`; it still runs inline.
- The Beginner and AI Builder agents are not built on `create_agent`, so a mid-turn message
  waits for the end of the turn there instead of being read mid-turn. It is still never a cancel.

## Background coding tasks (delegate_task)

- [ ] In Engineer mode, ask "Use delegate_task to add a `notes` text column to users." Leo says
      the task started and his turn ends. A pill reads **Coding task running · 0:0x**.
- [ ] While the pill is up, ask "what does the users table look like right now?". Leo answers
      without waiting for the task.
- [ ] While the pill is up, ask Leo to edit a file himself ("change the home page title").
      The status line says it is waiting for the coding task; the edit happens only after
      the pill clears.
- [ ] Ask for two delegate_task jobs in one message ("use two delegate_tasks: one adds X, one
      adds Y"). One pill reads **2 coding tasks running · M:SS**.
- [ ] While a coding task runs, open History and click **Save checkpoint**. It refuses with
      "A coding task is still editing files…". After the pill clears, saving works and the
      checkpoint includes the task's edits.
- [ ] When the task ends, the pill clears and Leo posts what it changed in a new message.
      Reload: history shows a grey "Coding task finished" line, not the raw report.
- [ ] Start a coding task, clear the input, press Stop. The pill disappears and no report
      arrives later.

## Checkpoint and git routes need sign-in

- [ ] Signed out (private window), open `https://<box>/api/checkpoints/uncommitted`. You get
      401, not a file list.
- [ ] `curl -s -o /dev/null -w '%{http_code}' -X POST https://<box>/api/checkpoints/discard`
      prints 401, and no files change on the box.
- [ ] Signed in, open the History panel. Checkpoints and the git graph load.
- [ ] Edit a file, click **Discard**. Files revert and the Undo card appears. Click **Undo** —
      the edit comes back. Discard again and dismiss the card — it goes away.
- [ ] In the git panel, check remote status, then **Pull**. It works as before (Rails restarts).

Needs `ASSEMBLY_AI_API_KEY` in the box's `.env` (force-recreate llamabot after adding it).

- [ ] On a box that never touched Settings → Voice Dictation, open Leo chat. The mic button
      sits next to Send. Settings shows the Voice Dictation toggle ON.
- [ ] Click the mic, say a sentence. The words appear in the input box and are NOT sent
      until you press Send.
- [ ] Turn the toggle OFF in Settings, reload chat. No mic button. Reload Settings — still OFF.
- [ ] Remove the key and force-recreate. No mic button, toggle greyed out, no console errors.
