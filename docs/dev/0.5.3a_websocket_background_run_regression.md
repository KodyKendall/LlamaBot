# What broke in 0.5.3a

## The short version

0.5.3a changed how the chat tracks a running agent. The change breaks after any
backend restart: you send a message, the spinner starts, and no answer ever comes
back. Refreshing the page fixes it until the next restart.

---

## What changed

**Before 0.5.3a:** the agent run was tied to your browser connection. If the
connection dropped, the run stopped. Simple and reliable.

**In 0.5.3a:** we made the run keep going in the background even if your browser
disconnects, so a long job wouldn't die on a connection blip. To let a
reconnecting browser catch up, the backend now numbers every message it sends (1,
2, 3...) and your browser remembers the highest number it has seen.

---

## Why it breaks

The backend's message counter only lives in memory, so a **backend restart resets
it to 1**. Your browser doesn't reset — it still remembers the last high number
from before.

So after a restart:

- Backend sends replies numbered 1, 2, 3...
- Your browser sees those numbers are lower than what it already has, decides
  they're old, and **ignores all of them** — including the "done" signal.
- Result: spinner spins forever, no answer appears.

This hits us constantly on the dev box because every backend code edit restarts
the backend.

Two smaller issues have the same root cause: if the backend restarts mid-job, the
answer is lost from the screen (you have to reload to see it), and long replies
that blip the connection now trigger a fragile reconnect-and-catch-up flow every
time.

---

## What to do

Go back to the old, connection-tied behavior, but keep the one small good part of
0.5.3a: the check that stops the same message from being sent twice.

**Trade-off:** with the old behavior, a long job will again stop if your browser
disconnects — which is the behavior you said you wanted. If we ever want jobs to
survive a disconnect, we'd need to rebuild the message-numbering so the counter is
stored permanently instead of wiped on every restart.

---

## How to reproduce

1. Send a message and let the agent answer.
2. Restart the backend.
3. In the same tab, send another message.
4. Spinner never stops, no answer. Refresh the page and it works again.

---

*No code has been changed — this is just the explanation.*
